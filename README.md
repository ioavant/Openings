# Openings — прототип

Ставит отверстия (Generic Model) там, где воздуховоды / трубы / лотки / короба
пересекают стены, балки, перекрытия, крыши и потолки из выбранных линков (или текущей модели).

## Тест через Add-in Manager

1. `dotnet build -c Debug` в папке `Openings\` — собираются обе половины (для net48 нужен установленный Revit 2022).
2. Add-in Manager → Load → команда `Openings.OpeningsCommand` (открывает главное окно):
   - Revit 2022–2024: `Openings\bin\Debug\Openings.dll` (net48, API 2022);
   - Revit 2025+: `Openings\bin\Debug\net8\Openings.dll` (net8, API 2025.0.2 из NuGet).

Отличия версий:
- Элементы линка, видимые на виде: в Revit 2024+ — точный коллектор `(doc, view, link)`; в 2022/2023 его нет,
  и `LinkViewCollector` берет элементы линка, попадающие в видимый объем вида (секущий бокс 3D-вида,
  подрезка + диапазон вида у плана, подрезка у разреза/фасада). Скрытые на виде категории/элементы линка там не учитываются.
- Настройки (`%AppData%\Vixeldorf\Openings\settings.json`) общие для всех версий; сериализация через
  `DataContractJsonSerializer` (есть и в net48, и в net8, без лишних DLL рядом с аддином).

## Окна

**Главное окно** — немодальное, как палитра ShaftMaster: остается открытым, пока работаешь в Revit; все действия
с моделью идут через ExternalEvent (`OpeningsSession` / `OpeningsHandler`, очередь действий).
- Сверху — из каких моделей брать стены / перекрытия (линки + текущая модель; запоминается по имени файла).
- Список отверстий проекта: ID, хост, форма, размер, уровень, низ от пола, элемент-хост, пол под отверстием, MEP-элементы.
  Обновляется при каждой активации окна; после расстановки подсвечиваются созданные/обновленные строки.
- **Place Openings** — расстановка; **Select** (или двойной клик) — выделить и показать в модели;
  **Delete** — удалить выбранные (с подтверждением); **Options…** — модальное окно настроек.
- **Edit Width** (отверстия в стенах) — строка в списке или, если ни одна не выбрана, выбор в модели.
  Нужен план: на нем рисуются две красные модельные линии — боковые грани отверстия (как эскиз в ShaftMaster:
  обычные линии, которые правишь инструментами Revit — Move, перетаскивание, Align). На палитре появляется
  полоса **Apply / Cancel**. Apply: новая ширина (диаметр у круглых) = расстояние между линиями вдоль стены,
  центр — посередине между ними; у круглых пересчитываются отметки низа. Линии удаляются.
  Отверстие помечается `manual=1` — повторный Place Openings его не пересчитывает (удали, чтобы пересчитать).
- **Section** (отверстия в стенах) — строка или выбор в модели → временный разрез `_Openings_Section #<ID>`
  по отверстию, смотрит на грань стены, захватывает пол, от которого считается высота. Предыдущие временные
  разрезы удаляются при создании следующего и при закрытии палитры (кроме открытого сейчас — его Revit удалить не даст).

**Options** — категории хостов, категории MEP (фитинги и арматура — отдельные пункты, по умолчанию выключены),
отступ, изоляция, круглые отверстия, объединение, шаг для поиска пола.
Generic Models — отдельный пункт: шахты ShaftMaster (и прочие generic models; сами отверстия игнорируются).

## Что обрабатывается

- **Выделены MEP-элементы** (отмеченных категорий) → отверстия только для них.
- **Не выделено ни одного** (ничего или только отверстия / стены / ...) → для всех MEP-элементов, видимых на активном виде.
- Фитинги / арматура — только если отмечены в Options. Без них воздуховод, заходящий в стену частично,
  все равно получает отверстие на всю толщину.
- Стены / перекрытия / ... — всегда только **видимые на активном виде** (в выбранных линках или в текущей модели).
  В плане перекрытие над уровнем обычно не видно — для отверстий в перекрытиях удобнее 3D-вид с секущим боксом.

## Как работает

1. **Пересечения** — тело MEP-элемента ∩ тело стены/перекрытия из линка (с учетом трансформации линка).
   Любое пересечение дает отверстие, даже если элемент заходит в стену лишь частично (дальше — фитинг):
   глубина — полная толщина хоста в этом месте (линия по нормали через тело хоста). Размер — полное сечение
   элемента, протянутое вдоль его оси от грани до грани (поэтому уже прорезанная стена не урезает отверстие),
   в осях хоста + изоляция (опция) + отступ с каждой стороны (по умолчанию 50 мм).
   У фитинга/арматуры направление и сечение берутся с коннектора, ближайшего к пересечению.
2. **Объединение** — элементы, перекрывающиеся на грани хоста (воздуховод + его фитинг в стене), всегда дают одно
   отверстие; при включенном объединении сливаются и отверстия с зазором ≤ заданного.
3. **Форма** — круглое, если все части круглые, идут почти перпендикулярно (≤ ~5°) и вместе дают круглое сечение
   (один элемент, или воздуховод + фитинг: ширина ≈ высота в пределах 5 мм); остальное → прямоугольное.
4. **Высота от пола** (стены) — шаг вдоль воздуховода за обе грани стены (+300 мм), луч вниз с высоты центра отверстия
   (не с низа: у воздуховода, лежащего на полу, низ с отступом уже в плите) до ближайшей **верхней** грани Floor / Roof
   (нижние грани пропускаются — старт внутри плиты над воздуховодом не дает «пол» сверху); результат = низ отверстия − верх пола
   (только отмеченные в окне линки / текущая модель) через служебный вид `_Openings_SearchView`. Разные полы с двух сторон → берется более высокий.
5. **Повторный запуск** — каждое отверстие помнит свой хост и MEP-элементы (`ApplicationDataId` =
   `host=<линк>:<id>;mep=<id>,<id>;x=<направление вдоль стены>[;manual=1]`). Новое отверстие забирает существующее с наибольшим числом общих
   MEP-элементов в том же хосте (при равенстве — ближайшее): тот же ElementId и Opening ID, марки сохраняются.
   - Воздуховоды сблизились и слились → остальные их отверстия удаляются.
   - Объединение распалось → большая часть сохраняет отверстие, остальные получают новые.
   - Элемент проверен, хост просмотрен, но пересечения больше нет → отверстие удаляется.
   - Если выбран один элемент из объединенного отверстия, остальные его элементы проверяются тоже.
   - Отверстия, созданные до появления ключей, сопоставляются по центру (50 мм) и не удаляются автоматически.

## Шахты ShaftMaster

Шахта узнается по Extensible Storage ShaftMaster (схема `f2a3b4c5-cafe-6005-b400-000000000001`, поле `ShaftId`;
запасной вариант — общий параметр ShaftId). Для перекрытий: отверстие = сечение шахты **без зазора и изоляции**,
сегменты одной шахты в одной плите дают одно отверстие, с воздуховодами не объединяется.
Прямоугольник → прямоугольное (оси по сторонам шахты), круг → круглое, иначе — **Free Shape**: профиль шахты
выдавливается через плиту, Opening Shape = `Free Shape`, Comments = `free shape` (если комментарий пуст).
Ширина/длина у free shape — габарит.

## Отверстия = Generic Model DirectShape (как в ShaftMaster)

Геометрия строится сразу в осях хоста, без семейства. Помечаются `ApplicationId = Vixeldorf.Openings`.
Данные — в общих параметрах (файл `%AppData%\Vixeldorf\Openings\Openings_SharedParams.txt`, GUID фиксированы
в `OpeningParams.cs`), привязанных к Generic Models:

| Параметр | |
|---|---|
| Opening ID | целое, уникальное в проекте: сохраняется при обновлении; у скопированного отверстия заменяется на новое |
| Opening Width / Opening Height | стена: вдоль стены / по высоте |
| Opening Width / Opening Length | перекрытие |
| Opening Diameter | круглые |
| Opening Depth | толщина хоста |
| Opening Bottom / Center From Floor | от верха пола (стены) |
| Opening Bottom / Center Elevation PBP | от Project Base Point |
| Opening Bottom / Center Elevation SP | общие координаты (Survey Point) |
| Opening Floor | стены: в какой пол/крышу попал луч — `<модель> : <категория> <id> — <тип>` |
| Opening Host, Opening MEP Elements, Opening Shape, Opening Host Type, Opening Level | текст |

Режим с загружаемыми семействами — позже; заготовка построителя семейств лежит в `Openings\Future\` (не компилируется).
